## Design Context

### Users
The sole creator and operator of the Mister Smith OS. Highly technical context requiring rapid visibility into operating system state and timeline events. Job to be done: orchestrating and monitoring local loopback API workflow executions, bootstrapping local NATS/Postgres instances, and tracking bounded autonomy sessions.

### Brand Personality
Mister Smith OS control panel. Agentic, authoritative, technical mastery. 
*Context Note:* This is not a consumer app or a generic SaaS dashboard. It is the primary "Cockpit" for a local, boundary-crossing AI operating system with supervised multi-agent execution.

### Aesthetic Direction
Extreme dark mode focus. Should feel like a precision local desktop shell or a specialized command center. The visual identity should lean heavily into deep blacks, precise mono-spaced data, and high-contrast status indicators (e.g., NATS connection states, agent heartbeats, timeline feeds) with a native macOS application feel.

### Design Principles
1. **Signal over noise**: Maximize data readability for extensive workflow logs and event timelines without compromising aesthetics. Form must strictly follow the function of operating a complex system.
2. **Technical precision**: High-fidelity dark mode execution that feels native, snappy, and authoritative. Avoid generic web-design tropes (e.g., unnecessary rounding, drop shadows on every card, whimsical animations).
3. **Cockpit realism**: Interfaces must reflect the true technical architecture (Tauri shell, Rust/Axum backend, NATS event bus, PostgreSQL state) and provide a window directly into the runtime's engine without abstracting away the power.
