     crates/mister-smith-transport/src/durable.rs
       #10780           🔵  DurableTransport architecture provides at-least-once
      delivery with acknowledgment control
         Reviewed complete DurableTransport abstraction to understand the 
     architecture introduced in PR #109. The module extends the fire-and-forget 
     Transport trait with JetStream-style durable consumer semantics through a 
     layered design. The MessageAcker trait provides a protocol-agnostic 
     interface for acknowledgment operations, allowing backend implementations 
     (like JetStreamAcker) to bridge generic operations to protocol-specific 
     mechanisms. DurableMessage encapsulates the envelope, reply subject, and 
     acker handle, ensuring messages must be explicitly acknowledged—dropping 
     without acking triggers redelivery after the consumer's ack timeout. The 
     architecture guarantees at-least-once delivery through automatic 
     redelivery, with exactly-once semantics achievable at the application layer
      via idempotent processing keyed by message_id. Publisher-side 
     deduplication prevents duplicate messages within the stream's dedup window.
      The DurableTransport trait adds durable_publish (with server persistence 
     acknowledgment) and durable_subscribe (named durable consumer for reconnect
      persistence) to support persistent messaging patterns.

         Reviewed complete NatsTransport implementation to understand how the

     async_nats with connection management through Arc<RwLock<Option<Client>>>, 
     implementing both fire-and-forget Transport operations (publish, subscribe,
      queue_subscribe, request) and durable JetStream operations. The 
     JetStreamAcker struct bridges the MessageAcker trait to NATS JetStream's 
     acknowledgment API, mapping all operations (ack, nak with optional delay, 
     term, in_progress) to TransportError::ProtocolError with descriptive 
     context. Durable publishing leverages JetStream's Nats-Msg-Id header for 
     server-side deduplication using the envelope's message_id, waiting for 
     persistence acknowledgment before returning. Durable subscriptions create 
     or attach to named pull consumers with explicit ack policy, configurable 
     timeouts, and max inflight acks from transport config. The implementation 
     includes defensive error handling: malformed messages that fail 
     deserialization are automatically terminated to prevent infinite 
     redelivery, with errors logged for observability. This provides a 
     production-ready JetStream backend with proper error propagation and 
     failure recovery.
